# Chakor Production Audit — 2026-08-07

Working document. Consolidated findings from a full codebase audit (security, DB, frontend, backend/infra).

Legend: `[ ]` open · `[x]` fixed · `[~]` partially addressed · `[!]` verified cannot reproduce / won't fix (documented)

## PHASE 1 — BLOCKERS

- [x] B1. npm audit: 5 vulns (3 critical, 2 high). Next.js 15.0.3: SSRF in rewrites (GHSA-p9j2-gv94-2wf4), unauthenticated Server Function disclosure (GHSA-955p-x3mx-jcvp); postcss XSS/file-read; sharp libvips CVEs. Fix: next → 15.5.x, react RC → react 19 stable.
- [x] B2. llama-server binds `0.0.0.0:4546` with NO auth (`lib/local-llama.ts:210`). Anyone on LAN gets free inference. Default should be `127.0.0.1` (LLAMA_HOST override preserved).
- [x] B3. Supervisor stuck: missing llama-server binary → spawn ENOENT emits `error` not `exit`; supervisor reports `running:true` forever, no crash-cap, no relaunch (`lib/llama-supervisor.ts:118-154`).
- [x] B4. Cross-user engine eviction kills in-flight chats: any user's chat with a different engine SIGTERMs llama-server mid-generation; partial response saved as complete (`app/api/chat/route.ts:79-84`, `lib/backends.ts:209-214`). No in-flight guard.
- [x] B5. First-user admin race: COUNT-then-INSERT with ~250ms bcrypt window → two concurrent first registrations both admin (`app/api/register/route.ts:27-39`, `lib/db.ts:192-196`). Needs transaction.

## PHASE 3 — RELIABILITY

- [x] R1. No timeout on inference fetches; hung llama-server hangs requests forever (all of `lib/providers.ts`, `lib/llama.ts:68`, `lib/agent.ts`). Agent loop: 5 sequential unbounded fetches.
- [x] R2. SSE parser fragile: multi-line frames dropped silently; HTTP error body discarded → user sees "HTTP 503" not real error (`ChatShell.tsx:940-945`, same in `Compare.tsx`, `settings/page.tsx`).
- [x] R3. Silent-failure mutations, no rollback/toast: pin/archive/move conv, Memory pin/edit, Notes patch, shareConv (`ChatShell.tsx:837-840,889`, `Memory.tsx:33-39`, `Notes.tsx:76-82`).
- [x] R4. User input lost on failed create: Notes composer reset before POST result, Memory clears text on failure (`Notes.tsx:60-73`, `Memory.tsx:31`).
- [x] R5. Compare page: no unmount cleanup → setState after unmount, streams leak (`Compare.tsx`).
- [x] R6. Missing confirmations on destructive actions: delete conversation, document, prompt, memory, note, revoke API key, remove Ollama model (multi-GB).
- [x] R7. AdminPanel mutations lack try/catch; offers Demote on own account (lockout risk) (`AdminPanel.tsx:117-121,297`).
- [x] R8. No structured logging anywhere; lib has zero console output; wide silent catches leave no trace.
- [x] R9. Download manager: no stall timeout, no disk-space check, no Range resume, `job.path` set before bytes written (`lib/download-manager.ts`).
- [x] R10. Unbounded queries: `getChunksForUser` (all chunks + full BM25 recompute per chat msg), `listMessages` (no LIMIT, includes base64 images) (`lib/db.ts:324-329,404-411`).
- [x] R11. Conversation import: 2000 unbatched statements, no transaction → partial import on crash (`app/api/conversations/import/route.ts:32-34`).
- [x] R12. Internal error text forwarded to clients: chat route streams raw err.message, agent includes upstream error body, documents route returns pdf-parse errors, /v1 returns e.message.
- [x] R13. No React error boundary — render throw blanks the app.
- [x] R14. Backpressure not observed on SSE enqueue (`app/api/chat/route.ts:229-230`).

## PHASE 4 — SECURITY

- [x] S1. No rate limiting anywhere: login brute-force open; register bcrypt-CPU DoS when open. In-memory limiter added (lib/ratelimit.ts); per-IP accuracy depends on the reverse proxy forwarding x-forwarded-for; limits are per-process (single instance OK).
- [x] S2. SSRF in `fetch_url` tool: blocklist checked only on initial URL; `redirect:'follow'` bypasses it; decimal/hex IP notation bypasses; no DNS resolution check (`lib/tools.ts:26-35,78-98`).
- [x] S3. API tokens stored plaintext in SQLite; direct equality lookup. Hash with SHA-256 (`lib/db.ts:76-83`, `lib/apiauth.ts`).
- [x] S4. Share slug only 40 bits entropy (`app/api/conversations/[id]/share/route.ts:17`) → 128 bits.
- [x] S5. Deleted users keep valid sessions until JWT expiry (existence not enforced in session callback) (`lib/auth.ts:42-53`).
- [x] S6. Docker: runs as root (no USER), no HEALTHCHECK, Ollama port 11434 exposed on all interfaces unauthenticated, model downloads land in /root/models outside /data volume.
- [x] S7. Google favicon service leaks searched domains to Google — contradicts privacy marketing (`ChatShell.tsx:116`).
- [x] S8. Username enumeration: register 409 message; login timing side-channel (early return before bcrypt).
- [~] S9. No inference quotas/length caps. Message-length caps added; full per-user quota system intentionally deferred.
- [x] S10. Missing security headers (no CSP/X-Frame-Options/etc. in next.config).
- [x] S11. `is_admin` PATCH accepts any number unvalidated; unknown actions silently succeed (`app/api/admin/users/[id]/route.ts`).
- [x] S12. Model path written to shell-consumed env file with weak quoting (`lib/local-llama.ts:166-178`).

## Verified clean (no action)

- SQL injection: fully parameterized everywhere.
- XSS: no dangerouslySetInnerHTML with user content; react-markdown without rehype-raw; urlTransform blocks javascript:.
- IDOR: all per-object queries ownership-scoped; admin routes all check isAdmin (refreshed from DB).
- Auth coverage: every app/api route calls auth(); only register/auth/v1 public by design.
- Uploads: 10MB cap, 20-doc cap, MIME whitelist, content into SQLite not disk.
- HF download path traversal: sanitizeRepo/sanitizeRepoFile reject .., absolute, non-.gguf.
- bcrypt cost 12; passwords never logged; password change requires current password.
- CSRF: SameSite=Lax JWT cookie.
- No hardcoded secrets; AUTH_SECRET generated per install.
- Pragmas: WAL, foreign_keys=ON on all paths; cascade deletes correct.
- No console spam, no TODO/FIXME in app code.
